はじめに#

「この人は伸びるのか？」
育成や採用に関わる人であれば、避けて通れない問いです。

しかし現実には、

  • 教えてみないと分からない
  • 半年〜1年経ってようやく見えてくる

というケースが多いのではないでしょうか。

本記事ではこの問題を構造で分解し、

  • 自走できる人材の見分け方
  • 自走できない人材の育成の型

まで整理します。

結論#

👉 自走力は「能力」ではなく「行動パターン」で見分けられる

そしてもう一つ重要な点があります。

👉 自走できない人材は、型で育てるべきである

自走力の正体#

自走できる人材は、次のループを持っています。

  1. 分からないことに直面する
  2. 仮説を立てる
  3. 調べる
  4. 試す
  5. 修正する

👉 このループが回る人が「自走できる人」です

見分け方#

① 初動#

  • 非自走型：止まる・指示待ち
  • 自走型：とりあえず触る・試す

👉 最初の一歩が違う

② 質問の質#

  • 非自走型：「分かりません」
  • 自走型：「〇〇だと思いますが合っていますか？」

👉 仮説の有無

③ 情報の扱い#

  • 非自走型：情報をそのまま受け取る
  • 自走型：比較・取捨選択する

④ 再現性#

  • 非自走型：一度できても再現できない
  • 自走型：手順を言語化できる

⑤ 違和感#

  • 非自走型：指示通りにやる
  • 自走型：「これおかしくないですか？」

👉 構造を見る力

なぜ見分けが重要か#

ここを間違えると、ほぼ確実に失敗します。

👉 「自走前提の育成」を非自走型に適用してしまう

結果👇

  • 伸びない
  • 本人も苦しい
  • 教える側も疲弊する

育成の型（ここが本題）#

非自走型に必要なのは「自由」ではなく👇

👉 型（フレーム）です

型①：強制アウトプット#

やること#

  • 説明させる
  • 図にさせる
  • 手順を書かせる

理由#

👉 理解していないとアウトプットできないため

インプットだけでは「分かった気」になりますが、
アウトプットで初めて理解の有無が露呈します。

型②：具体接続#

やること#

  • 実際の環境で説明させる
  • 自社システムに当てはめる

理由#

👉 抽象だけでは理解が定着しないため

特にインフラ・ネットワークは、

  • 見えない
  • 抽象度が高い

👉 現実と接続しないと理解できない

型③：仮説強制#

やること#

  • 「原因を3つ考えて」
  • 「どれが一番ありそう？」

理由#

👉 思考しないと前に進めない構造を作るため

型④：調べ方の型を教える#

やること#

  • 検索ワードを教える
  • 情報の優先順位を教える
  • 調査手順を固定化する

理由#

👉 非自走型は「調べ方」が分からないため

型⑤：小さな成功体験を作る#

やること#

  • 解けるレベルの課題を出す
  • 解決まで伴走する

理由#

👉 「やればできる」という回路を作るため

これがないと永遠に動きません。

現実的な期待値#

重要です。

  • 自走型 → 早く伸びる
  • 非自走型 → 安定して伸びる（時間はかかる）

👉 目安：3〜5年

これは異常ではなく、現実的なラインです。

よくある失敗#

  • 放置して自走を期待する
  • 抽象的な指示を出す
  • 成長速度を比較する

👉 すべて構造ミスです

まとめ#

  • 自走力は行動パターンで見分ける
  • 非自走型は「型」で育てる
  • 問題は個人ではなく設計にある

最後に#

育成で失敗する最大の原因はこれです。

👉 「人に期待しすぎること」

構造で詰まっている方へ

業務・IT・収益構造などで違和感がある場合、 構造を整理することで問題の本質が見えることがあります。
