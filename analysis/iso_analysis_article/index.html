なぜISOや内部統制は形骸化するのか？評価が組織を歪める構造

ISO、内部統制、SLQDCは本来現場を良くするための仕組みである。 それなのになぜ多くの組織でやること自体が目的になってしまうのか。 評価、形式、過去の学習という3つの視点から、その構造を整理する。

結論#

組織は、本来の目的ではなく、評価されるものに最適化される。

本来の目的と評価のズレ#

本来の目的：

  • 品質向上
  • 安全確保
  • 不正防止
  • 継続的改善

実際の評価：

  • 書類があるか
  • 手順通りか
  • 監査に通るか
  • 数字が基準内か
  flowchart TD
    A["本来の目的"] --> B["測りやすい指標"]
    B --> C["人は評価に最適化"]
    C --> D["形式が増える"]
    D --> E["目的からズレる"]

形骸化はループで進む#

  flowchart TD
    A["評価基準"] --> B["行動"]
    B --> C["形式増加"]
    C --> D["形式固定"]
    D --> E["目的ズレ"]
    E --> A

これは一度回り始めると止まらない。

なぜやめられないのか#

  • 外部圧力（顧客・認証）
  • 組織防衛（責任回避）
  • 不安（代替がない）
  flowchart TD
    A["外部圧力"] --> D["やめられない"]
    B["組織防衛"] --> D
    C["不安"] --> D

👉 価値があるからではなく、外せないから続いている。

SLQDCも同じ構造#

本来：現場改善のための指標
現実：評価対象

  flowchart TD
    A["SLQDC"] --> B["評価対象"]
    B --> C["数字を守る行動"]
    C --> D["本質ズレ"]

具体例#

  • Safety：事故を隠す
  • Quality：不良を軽微化
  • Delivery：無理な前倒し
  • Cost：必要投資削減

👉 指標が悪いのではない。評価の使い方が問題。

内部統制が機能しない理由#

  flowchart LR
    A["作業"] --> B["チェック"]
    B --> C["承認"]
    C --> D["保存"]

本来：

  flowchart LR
    A["異常検知"] --> B["原因分析"]
    B --> C["改善"]
    C --> D["標準化"]

👉 チェックはあるが改善につながらない

文化は過去の学習でできる#

  flowchart TD
    A["問題提起"] --> B["仕事増"]
    B --> C["評価低下"]
    C --> D["学習"]
    D --> E["問題を出さない"]

👉 現場は合理的に適応している

再設計の方向#

  • 問題を出した人を評価
  • 改善を評価
  • 隠すと損になる設計
  flowchart TD
    A["問題"] --> B["評価"]
    B --> C["改善"]
    C --> D["成果"]
    D --> A

まとめ#

  • 目的ではなく評価に最適化される
  • 形式が本質を置き換える
  • 制度は外せない
  • 文化は過去の罰で形成される

最後に#

ISOや内部統制が機能していないのではない。
今の評価設計に対して、極めて正しく機能しているのである。
